# PathSnap — GPS trajectory map matching

A reproducible student implementation for matching noisy GPS observations to a directed road network.

## Dataset layout

Place the supplied data under `data/raw/` with partitions `train/` and `student_test/`. Each trip directory contains `.track`, `.nodes`, `.arcs`, and `.route` files. The 10-trip student-test partition is for development evaluation. Keep the evaluator partition separate and server-side.

## Setup

```bash
python -m venv .venv
# Windows: .venv\\Scripts\\activate
# macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
```

## Explore the dataset

```bash
python -m src.pathsnap.explore --data data/raw --out results/eda
```

## Train and compare five models

```bash
python -m src.pathsnap.train --data data/raw --out results --artifacts artifacts
```

The training script uses GroupKFold grouped by trip, fits five model families, and writes `results/model_comparison.csv` plus `artifacts/best_model.joblib`.


Laptop 1 hosts the API. Make sure the project, saved model, dependencies, and data are present there. 
```powershell
.\.venv\Scripts\Activate.ps1
uvicorn src.pathsnap.api:app --host 0.0.0.0 --port 8000
```

Keep the API terminal open. Check it on Laptop 1 at `http://127.0.0.1:8000/docs`. In another PowerShell terminal, run `ipconfig` and note the Wi-Fi adapter's IPv4 address.

On Laptop 2, activate its environment, install dependencies, and start Streamlit:

```powershell
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
streamlit run app.py
```

Open `http://localhost:8501`. In the app's **API URL** field, enter `http://<LAPTOP-1-IP>:8000` (replace `<LAPTOP-1-IP>` with the IPv4 address from Laptop 1). Check connectivity at `http://<LAPTOP-1-IP>:8000/health`. The API serves predicted-route maps and keeps evaluator reference routes out of the browser.

If port 8000 is already in use on Laptop 1, start the API with `--port 8001` and use `http://<LAPTOP-1-IP>:8001` in the API URL and health check instead. The backend also needs the dataset under `data/raw/`, including `student_test/`; otherwise `/trips` cannot list trips.

## Current experiment snapshot

The current executed comparison is in `results/model_comparison.csv`. Five models were trained; Random Forest was selected with CV candidate Macro F1 0.873 and student-test Top-1 accuracy 0.71. The HMM/Viterbi experiment increased measured route continuity from 0.317 to 0.788 while reducing pointwise Top-1 accuracy from 0.711 to 0.531. Optuna ran five TPE trials; the tuned model did not outperform the untuned model on the measured comparison. See the PDF draft for detailed metrics and caveats.

## Important methodology and integrity notes

* `.arcs` row position is the arc ID; `.route` stores the reference arc sequence.
* The training labels in this baseline are generated by assigning each sampled GPS point to its closest segment among the trip's reference-route arcs. This is a geometric weak-label assumption, not a provided observation-to-arc alignment.
* Candidate miss rate must be reported: the correct reference segment may not appear in the nearest-candidate set.
* The evaluator partition must not be used for training, tuning, feature selection, or UI-side ground-truth display.
* Do not report any metric until the corresponding experiment has actually completed. Preserve logs and random seeds.
* The current implementation is a student-side baseline and should be validated and improved before final submission.
